# AgentNote AI 사용성 전략

작성일: 2026-05-12

## 현재 AI 기능의 위치

AgentNote에는 현재 두 가지 AI 성격의 기능이 있다.

- AI 매물 추천기: 고객 조건과 매물을 룰베이스로 비교해 조건 적합도를 보여준다.
- AI 브리핑: 후보 매물 2~5개를 비교해 상담 메모, 고객용 카톡 문안, 소개서 문구를 만든다.

두 기능은 데모와 상담 준비에는 임팩트가 있지만, 중개사의 매일 반복 업무에서는 사용 빈도가 낮을 수 있다. 특히 사용자가 고객과 통화하거나 카톡을 주고받는 순간에는 별도 AI 페이지로 이동해 고객과 매물을 다시 선택하는 과정이 부담이 될 수 있다.

## 한계

- 별도 페이지 진입이 필요해 상담 중 즉시 쓰기 어렵다.
- 후보 매물 데이터가 충분히 입력되어 있어야 결과 품질이 올라간다.
- 실제 업무에서는 매물 추천보다 고객 메모 정리, 다음 할 일, 카톡 답장 초안이 더 자주 필요하다.
- AI가 점수와 순위를 정하는 구조는 신뢰 문제를 만들 수 있으므로 계속 룰베이스 점수를 기준으로 유지해야 한다.

## 더 자주 쓰일 AI 후보

### 1. 고객 상담 메모 AI 정리

사용 위치:

- 고객관리
- 빠른 고객 등록
- 고객 수정 화면

사용자가 대충 적은 상담 메모에서 다음 항목을 정리한다.

- 희망 지역
- 예산
- 매물 종류
- 중요 조건
- 다음 할 일
- 고객에게 물어볼 질문
- 고객용 짧은 카톡 답장 초안

예상 사용 빈도가 가장 높다. 상담 직후 메모를 정리하고 다음 액션을 잡는 흐름은 거의 모든 고객에게 반복된다.

### 2. 소개서 문구 AI 다듬기

사용 위치:

- 소개서 작성 화면

매물 설명, 장점, 확인 필요 사항을 소개서 문체로 다듬는다. 현재 소개서 작성 흐름에 자연스럽게 붙일 수 있다.

### 3. 상담 후 할 일/일정 생성 보조

사용 위치:

- 고객관리 메모
- 일정관리

상담 메모에서 "미팅 잡기", "계약서 작성", "잔금 확인" 같은 다음 액션 후보를 제안한다. 자동 저장보다는 사용자가 확인 후 일정에 추가하는 방식이 안전하다.

### 4. 고객 카톡 답장 생성

사용 위치:

- 고객 상세
- 고객 메모

AI 브리핑보다 가볍게, 현재 고객의 조건과 최근 메모를 바탕으로 짧은 카톡 문안을 생성한다.

## 1순위 추천

1차 MVP는 **고객 상담 메모 AI 정리**가 가장 적합하다.

이유:

- 사용 빈도가 높다.
- 고객관리 화면 안에서 바로 쓸 수 있다.
- 매물 데이터가 부족해도 가치가 있다.
- 결과를 자동 반영하지 않고 "확인 후 적용"으로 만들면 안전하다.
- 기존 AI 비용 방어 로직과 gpt-5-nano 설정을 재사용할 수 있다.

## 권장 MVP 범위

고객관리 메모 입력 영역 옆에 `AI로 조건 정리` 버튼을 둔다.

요청 예:

```json
{
  "memo": "신사동 사무실 찾음. 보증금 6000 이하, 월세 220 이하. 엘베 있어야 하고 카페 용도 문의. 전용 30평 이상이면 좋음.",
  "currentCustomer": {
    "name": "이름 일부 또는 비식별 표시",
    "propertyType": "사무실"
  }
}
```

응답 예:

```json
{
  "mode": "llm",
  "result": {
    "summary": "신사동 사무실을 찾는 고객으로, 카페 용도 가능 여부와 엘리베이터 조건이 중요합니다.",
    "suggestedFields": {
      "preferredArea": "신사동",
      "propertyType": "사무실",
      "budget": "보증금 6000만원 이하, 월세 220만원 이하",
      "conditions": ["엘리베이터 필요", "카페 용도 가능 여부 확인", "전용 30평 이상"]
    },
    "nextActions": ["카페 용도 가능 매물 확인", "엘리베이터 있는 매물 우선 확인"],
    "questionsToAsk": ["주차 조건도 중요하게 보시나요?"],
    "customerMessage": "말씀주신 조건 기준으로 신사동 사무실 중 엘리베이터와 카페 용도 가능 여부를 먼저 확인해서 후보를 추려보겠습니다."
  }
}
```

## 구현 원칙

- OpenAI API 호출은 서버/API route에서만 한다.
- 모델 기본값은 `gpt-5-nano`로 유지한다.
- 기존 비용 한도 로직을 재사용한다.
- 전화번호, 이메일 등 불필요한 개인정보는 LLM에 보내지 않는다.
- 메모 길이는 제한한다.
- AI 결과는 자동 저장하지 않는다.
- 사용자가 확인 후 각 필드에 적용하도록 한다.
- API 키가 없거나 한도를 넘으면 템플릿 기반 정리 또는 안내 문구로 fallback한다.

## 이번 안정화 작업에서 반영한 최소 진입점

이번 작업에서는 새 OpenAI API를 늘리지 않고 기존 화면으로 이어지는 진입점만 강화한다.

- 고객관리 카드의 `AI 추천 보기` 문구를 `추천 매물 보기`로 바꿔 업무 흐름을 더 명확하게 한다.
- 고객관리 카드에 `상담 문구 만들기` 버튼을 추가해 해당 고객을 선택한 상태로 AI 브리핑 화면에 진입한다.
- AI 매물 추천기 결과의 `AI 브리핑 만들기` 버튼은 선택 고객과 추천 매물 1개를 AI 브리핑 화면으로 넘긴다.
- AI 브리핑 화면은 전달받은 고객/매물 후보를 미리 선택하되, 실제 OpenAI 호출은 사용자가 `AI 브리핑 생성`을 누를 때만 발생한다.

이번 작업에서는 고객 상담 메모 AI 정리 API는 아직 추가하지 않는다.

이유:

- 현재 우선순위는 소개서 이미지, 일정 카운트, 정산 월별 보기 안정화다.
- 새 API와 저장 UI를 추가하면 README 전 검증 범위가 커진다.
- 기존 AI 브리핑/추천기 안정성을 깨지 않는 것이 더 중요하다.

README 작성 후 다음 작업으로 고객관리 화면에 작은 MVP를 붙이는 것을 추천한다.
